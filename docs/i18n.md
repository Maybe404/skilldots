# 界面语言与术语表

skd 的界面文字有英文和简体中文两种，选择方式和实现原则见 [design.md 的“语言”一节](design.md#语言)与 README 的 Language 一节。这份文档给两件事：给翻译和新增文案的人一份约定，给读中文输出的人一份术语对照。

## 新增或修改文案

1. 英文写在显示它的地方：`i18n.Sprintf("copied %s → %s", a, b)`、`i18n.Errorf(…)`、`i18n.T("…")`。**英文就是键**，改英文要同步改 `internal/i18n/zh/*.txt` 里的键。
2. 在 `internal/i18n/zh/` 的某个 `.txt` 里加一对：
   ```
   @ copied %s → %s
   = 已复制 %s → %s
   ```
   文件里 `\n`、`\t`、`\\` 是转义；一对与下一对之间空一行；`#` 开头是注释。
3. 表格、包装函数或包级变量里的文案先用 `i18n.M("…")` 标记，显示处再 `i18n.T(变量)`；复数用 `i18n.Count(n, "%d pack", "%d packs")`（中文只需要后一条）。
4. 跑 `go test ./internal/i18n`：漏译、多余的译文、动词对不上、顺序调换却没用 `%[2]s`、用了 `fmt.Errorf`/`errors.New` 写人读的文案、把带字母的字面量直接交给 `dim`/`warn`/`sg`/`hint`/对话框函数，都会报错（确实不该翻译的行末加 `// i18n:raw`）。`I18N_SKELETON=/某路径/skel.txt go test ./internal/i18n` 会把缺的条目按 `.txt` 格式写出来。
5. 写进文件、给机器读的东西不进 `i18n`：JSON 字段、库里的文件、commit 信息。`--json` 下进程语言固定为英文，所以人读的文案出现在 JSON 里也是英文（见 design.md）。

## 排版约定

- 中文与英文、数字之间留一个空格：`已引入 3 个 skill`。
- 中文句子用全角标点（，。：；（）），命令、路径、选项、代码里的标点保持半角。前缀 `错误：`、`警告：` 自带全角冒号，后面不再补空格（`cli.label`）。
- 不要逐词翻译。英文里的“被动 + 介词”改成中文习惯的说法；一句话里的几个值要换顺序时用 `%[2]s`。
- 宽度按显示格数算，别按字符数；对齐用 `pad`/`fit`，截断用 `i18n.Truncate`，不要写 `%-13s` 去对齐可能是中文的东西。
- 表头里的产品词保持英文（PACK、SKILL、COMMIT、TARGET），其余译成中文。
- 命令名、选项名、skill 名、路径、`skills.toml` 的键、环境变量永远是原样。

## 中文怎么出现

- 命令行：`--lang zh`，或 `SKILLDOTS_LANG=zh`，或 `skd config set lang zh`；系统是中文时 `auto` 自己就是中文。
- 仪表盘：`,` 打开设置页，选 `lang`，输入 `zh`、`en` 或 `auto`，立即生效。
- agent 读输出：用 `--json`（任何语言下都是英文，字节相同），不要解析人读的文字。
