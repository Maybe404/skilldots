@ Resolve the conflicts of a shelved update, as you would finish a git merge
= 解决已搁置更新的冲突，就像完成一次 git merge

@ An update merges upstream's changes into a vendored skill you changed. When both sides changed the same lines (or one removed a file the other changed) the update of that skill is shelved: the skill stays as it is until its conflicts are resolved. Without arguments, resolve lists the shelved skills. resolve <skill> writes the merge into the skill's files with git's conflict markers (<<<<<<< local, =======, >>>>>>> upstream) after setting the skill aside in the trash, and marks the files unmerged in the library's git index, so git status, git diff and git checkout --ours/--theirs <file> work as in a git merge. A file removed on one side, or not text, gets the upstream version beside it as <file>.upstream (or an empty <file>.upstream-deleted where upstream removed it): keep one and delete the other. Edit the files, then --continue takes the result (it refuses while a marker or such a file is left); --abort puts the skill back as it was, still shelved. Until then agents linked to the skill read the files with their markers.
= 更新会把上游的改动合并进你改过的引入 skill。如果两边改了同样的行（或者一边删掉了另一边改过的文件），这个 skill 的更新就会被搁置：在冲突解决之前，skill 保持原样。不带参数时，resolve 列出已搁置的 skill。resolve <skill> 先把这个 skill 放进回收站，再把合并结果连同 git 的冲突标记（<<<<<<< local、=======、>>>>>>> upstream）写进它的文件，并在资料库的 git 暂存区里把这些文件标为未合并，所以 git status、git diff 和 git checkout --ours/--theirs <文件> 的用法和 git merge 时一样。一边删掉的文件或非文本文件，会在旁边放一份上游版本 <文件>.upstream（上游删掉的则放一个空的 <文件>.upstream-deleted）：留下一个，删掉另一个。编辑完文件后，--continue 采用结果（还有冲突标记或这类文件时会拒绝）；--abort 把 skill 恢复原样，更新仍然搁置。在此之前，链接了这个 skill 的 agent 读到的是带冲突标记的文件。
