@ Your changes to a vendored skill stay yours (skd update merges upstream's changes into them); nothing is ever sent upstream unless you run this. contribute <skill> --pr opens a pull request on the pack's GitHub repository from a branch skilldots/<skill>-<time> (pushed to the repository when you may push there, else to your fork, which gh makes); --push pushes the change straight to the pack's branch, when you may. The change is committed, with your git identity and -m as the message, in a clone of its own in the cache, never in the library. The skill must be based on upstream's current version (skd update first), and --pr needs gh, logged in. contribute <pack> sends every skill of the pack you changed, and every skill you made in it (skd new --in), in one commit. For your own repository (skd own) it pulls first when the repository moved on, merging as skd update does, and pulls back after a push, so nothing is left marked as changed. --dry-run shows the repository, the branch, what is possible and the diff, and sends nothing; without a terminal --yes is needed to send. Without a skill, contribute lists the contributions on record; --refresh asks GitHub for the state of the pull requests.

@ sync commits the library, fetches its git remote and merges what the remote has that the library has not (git merge, never rebase; what the merge brings in is linked), then pushes, with the upstream snapshots. When both sides changed the same lines the sync is shelved: the merge is aborted, the library stays as it was, nothing is pushed, and the conflicting files are listed. sync --resolve redoes the merge and leaves git's conflict state in the library (conflict markers, files unmerged in the index: git status, git diff and git checkout --ours/--theirs work); agents linked to skills among them read the markers until it is finished. Edit the files, then sync --continue commits the merge and pushes (it refuses while a marker is left); sync --abort gives up (git merge --abort). private/ is a separate repository and is never pushed.
= sync 提交资料库，拉取它的 git 远程仓库，把远程有而资料库没有的改动合并进来（git merge，从不 rebase；合并进来的内容会被链接），然后连同上游快照一起推送。两边改了同样的行时，同步被搁置：合并被放弃，资料库保持原样，什么也不推送，并列出冲突的文件。sync --resolve 重做合并，把 git 的冲突状态留在资料库里（冲突标记、暂存区里未合并的文件：git status、git diff 和 git checkout --ours/--theirs 都能用）；在完成之前，链接了其中 skill 的 agent 会读到冲突标记。编辑完文件后，sync --continue 提交合并并推送（还有冲突标记时会拒绝）；sync --abort 放弃（git merge --abort）。private/ 是单独的仓库，从不推送。
