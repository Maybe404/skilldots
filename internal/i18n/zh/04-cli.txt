# Command line: help texts, tables, prompts, progress and results.

@ Show or change your settings (editor, theme, lang)
= 查看或修改设置（editor、theme、lang）

@ Settings are per user and per machine, in %s. An empty value unsets a setting. lang is the language of skd's own text: en, zh or auto (the system's). set changes only that setting's line: your comments and other lines stay, and so does a comment at the end of that line (unsetting removes the line with it; a value written over several lines is the exception: then the file is written again, without comments). Lines end like the file's (LF or CRLF).
= 设置按用户、按机器保存，位于 %s。值为空表示取消该设置。lang 是 skd 自身文字的语言：en、zh 或 auto（跟随系统）。set 只改动该设置所在的那一行：你的注释和其他行都保留，那一行末尾的注释也保留（取消设置时整行一起删除；值跨多行是例外，那时会整个文件重写，注释不保留）。换行符与文件原有的一致（LF 或 CRLF）。

@ Open a skill's directory in your editor
= 用编辑器打开 skill 的目录

@ The editor is the editor setting (skd config set editor <command>), else $VISUAL, else $EDITOR, else VS Code, Cursor, Zed or Sublime Text when installed, else the system's default opener. A vendored skill (or one an application ships) is replaced on update, so skd does not open it as is: at a terminal it asks whether to fork it first; otherwise it refuses unless --fork (copy it into skills/, or private/ with --private, and open the copy) or --force (open the files that will be replaced) is given.
= 编辑器依次取：editor 设置（skd config set editor <command>）、$VISUAL、$EDITOR，再是已安装的 VS Code、Cursor、Zed 或 Sublime Text，最后用系统默认的打开方式。引入的 skill（或应用自带的 skill）会在更新时被替换，所以 skd 不会直接打开它：在终端里会先问你是否 fork；否则会拒绝，除非给了 --fork（复制到 skills/，加 --private 则复制到 private/，并打开副本）或 --force（打开将被替换的原文件）。

The record is %s in the library: it is committed and pushed with it, so another machine sees it after a clone. Reading it needs no network.
= 每次 `skd update` 都会为它更新的每个来源记录：新旧 commit，发生变更、新增、移动、在上游消失或在上游出现的 skill，以及涉及这些 skill 的上游 commit 的标题（最多 %d 条）。记录保存在资料库里的 %s：它随资料库一起提交和推送，所以另一台机器 clone 之后也能看到。读取它不需要网络。
